## 复现

```bash
python3 -m unittest discover -s tests -v
python3 scripts/validate_distribution.py
python3 scripts/build_plugin.py
```

测试设置 `GIT_CONFIG_GLOBAL` / `GIT_CONFIG_NOSYSTEM` 以隔离用户机器上的 Git 全局配置，避免执行用户现有的全局 Hooks。测试所需身份写入各临时仓库的本地 Git 配置。临时项目禁写 Python 字节码缓存，避免一秒内修改同长度文件时复用旧 `.pyc`，保证修复重跑测试的确定性；不修改用户项目的缓存策略。

## 实际验收边界

验证覆盖本地运行时、发行包和协议交接。宿主完整安装流程、Windows、真实 GitHub API 与生产部署系统未纳入本轮自动化验收。

专业能力报告使用明确的测试 fixture 验证交接协议、门禁和证据新鲜度；测试没有调用模型，不能证明方案和审查的语义质量。调研采集器、Git 操作与测试命令则在临时仓库中实际执行。

GitHub 适配器参数参照官方 CLI 文档，服务契约测试使用明确模拟的数据。部署接口的协议和阶段顺序由运行时检查，具体项目的部署脚本、异步成功状态和健康验证仍需在其环境中验收。

本地审批注记与状态文件不是服务端签名，Git Hook 不是不可绕过的安全边界。CI/组织级审批可使用相同产物契约独立实现。
