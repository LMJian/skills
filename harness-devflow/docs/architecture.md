# 通用 Harness 设计

## 核心机制

运行时组织需求与验收、产物校验、依赖批次、验证修复循环和任务恢复。设计深度与交付终点独立配置；设计确认、隔离工作树、远端交付、发布与知识沉淀按实际任务选择。专业 Skills 通过阶段契约提供调研、设计和审查方法。

| 能力 | 实现方式 |
| --- | --- |
| 任务跟踪 | 用户目标与稳定 task ID；外部 issue 链接作为可选资料 |
| 设计评审 | 本地 Markdown、内容哈希与审查记录；按配置加入设计确认，可附文档链接 |
| 接口更新 | interfaces 命令适配器，记录契约文件、生成结果和依赖更新 |
| 测试验证 | 项目 checks 与 stage_checks，执行项目工具链中的检查命令 |
| 代码交付 | push/pr/monitor 适配器，返回统一结果供运行时验证 |
| 发布部署 | 风险、回滚、可观测性证据与项目配置的部署适配器 |
| 知识归档 | 可选本地知识快照及批准来源，外部同步按任务要求执行 |
| 宿主接入 | Skills 指导 Agent，标准库 CLI 管理共享的流程状态 |

## 分层

1. **Skills**：14 个流程入口保持阶段契约，包内 `brownfield-recon` 和 `server-tech-design` 提供调研、服务端设计与设计审查方法，不要求另外安装技能包。
2. **Runtime**：验证输入、阶段转换、产物和实际命令记录。只此层写状态。
3. **Git executor**：单模块直接使用当前分支，或建立模块 worktree、逐批合并；验证实际提交与检查证据。
4. **Adapters**：执行项目选定的平台动作，报告真实结果；默认配置没有外部适配器。
5. **Artifacts**：人可读文档与机器报告；成为下一阶段的输入及恢复依据。

`engine.py` 是阶段契约的可执行真源，`model.py` 解析 profile、endpoint、条件阶段和执行顺序，`runner.py` 负责子进程生命周期。状态保存完整阶段目录、实际启用项、顺序和覆盖配置；被排除的阶段有明确策略原因。

`capabilities.py` 通过逻辑名称选择包内或项目内专业 Skill。包内路径从运行时自身位置解析，项目扩展从 `.harness/skills/<name>/` 解析。`recon` 在 intake 内按需执行；backend 的 design/design_audit 使用服务端设计方法，其他领域默认通用方法。能力选择不添加流程阶段，也不代替真实检查。

每次专业调用保存请求、Skill 与相对资源快照、内容摘要、产物及发现。Agent 阅读快照执行方法，运行时验证结果与主阶段报告的关联；CLI 本身不调用模型。收集脚本通过现有命令运行器实际执行，保留退出码和日志。准备调用或仅生成文件不会通过门禁；未完成、阻断或证据变化都会阻止推进。调用绑定、源版本和历史可恢复，设计审查结果必须进入主阶段报告。详见[专业能力契约](../references/capabilities.md)。

工作区与命令结果由内容指纹关联，不靠 mtime。项目配置与任务选择冻结在状态中。任务重配和项目配置同步保留历史并失效受影响后缀；单纯并发/超时等操作参数变化不触发设计重批。命令证据绑定命令配置哈希，任何新提交仍使已完成的代码验证失效。

计划由真实任务、验收映射、验证方法和依赖批次组成。模块完成需提供所有计划任务 ID。`auto` 根据模块数选择 checkout/worktree，不改变用户分支。选择 checkout 时拒绝多模块共用，以免破坏并行隔离语义。

## 恢复语义

状态、命令记录和事件历史在同一个 JSON 事务内写入，避免多个状态文件各自成功造成互相漂移。
文档与命令日志先产生，再在状态中引用；未引用的草稿/日志不会被当作阶段完成证据。
工作树创建/合并包含外部 Git 操作，采用确定性路径、提交祖先检查及实际 Git 状态实现恢复。
部分合并成功后重入可继续；冲突保持原状等待正确解决。

长命令不持有状态锁，先记录 in-flight，再执行，最后回填。任务重开/中止会检查 in-flight。
进程崩溃后需检查日志与外部副作用，确认进程结束后才能 abandon；不把未知结果当作可安全重试。
适配器使用稳定幂等键并自行协调服务端结果，本地运行时不声称能保证跨机器 exactly-once。

## 默认策略

首次使用需明确真实项目检查命令；空检查配置不能通过 review。所有平台账号和部署环境均可省略；本地终点自动排除远端及发布阶段。标准流程默认设计审查和测试方案，轻量流程将简短实现思路与验证方案放进需求。设计确认只在明确选择时要求，发布配置默认开启。

集成检查配置非空时默认执行，优先推送前验证；依赖远端预览时可放在推送后。PR 终点在创建评审请求后完成，merged 终点在合并后完成，只有 deployed 终点经过发布门禁及部署。知识默认关闭；启用后默认本地自动归档，人工审查可配置，no_changes 无审批、无快照。
不默认发送消息或评论、合并远端 PR、安装全局工具、启用 Hooks、创建计划任务或执行生产部署。
这些动作由实际任务授权与宿主权限决定，不以模板中的配置代替用户意图。

模块任务默认串行。具备实际能力且获得授权时可按波次并行；任何失败 worker 都必须有结果处理。
独立 Reviewer 能提升审查覆盖，但模型、Agent 数量和供应商不成为运行时依赖。

## 范围边界

本地 CLI 验证证据的结构、关联与新鲜度；设计语义、测试有效性、部署健康语义由 Agent 与项目工具共同验证。
审批注记不是身份服务；自定义 adapter 是可信执行边界。要实现组织级强门禁，可以把相同报告契约接入 CI，并增加服务端签名/审批身份，而无需把供应商 API 写入核心。

本版本交付可运行插件与扩展接口，未提供任意阶段重排、绕过 PR 的独立部署终点、内置托管调度、生产云部署实现或跨设备同步。v0.2 的 schema 2 状态在内存中补充能力默认值，读取不写文件，下一次正常修改时保存；不会仅因新增默认值重开已完成阶段。v0.1 活动任务仍使用旧包完成/导出后另起新任务。
